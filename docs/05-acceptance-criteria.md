# 검증 기준

## 구현 완료 검증 기준

아래 기준은 [계산 및 통계 정책](04-calculation-and-statistics.md)을 따른다. 급여 주기 관련 기준은 문서의 구간 제안을 전제로 하며, 통계용 급여 기준일 정책 확정 시 함께 점검한다.

1. 급여·기타 수입, 지출·저축을 등록하고 다시 조회할 수 있다.
2. 수동·자동 등록 여부와 관계없이 모든 수입·지출·저축 기록을 수정·삭제하면 해당 기간의 통계에 반영된다.
3. 예시 데이터를 입력하면 [계산 예시](04-calculation-and-statistics.md#계산-예시)의 급여 주기·월·연 통계 결과와 일치한다.
4. 급여일 당일 기록은 새 급여 주기에, 전날 기록은 이전 주기에 포함된다.
5. 월말·연말 경계에서 기록이 누락되거나 중복 집계되지 않는다.
6. 저축은 잔여액에서 차감되지만 소비 지출 합계에는 포함되지 않는다.
7. 입력 금액이 0 이하이거나 날짜가 유효하지 않으면 저장되지 않는다.
8. 모든 기록이 없는 기간은 합계를 0으로 표시한다. 수입만 있는 기간은 지출·저축이 0이고 잔여액은 수입과 같다.
9. 통계 조회를 반복해도 수입·지출 기록이 생성되거나 중복 등록되지 않는다.
10. 화면을 새로고침해도 저장한 내역이 유지된다.
11. 이전 기간에 잔여액이 있어도 다음 기간으로 이월되지 않는다. 지출·저축이 수입을 초과해도 저장할 수 있고 잔여액은 음수로 표시된다.
12. 기록 날짜를 다른 월·급여 주기로 수정하면 이전 기간에서 제외되고 새 기간에 반영된다. 연간 합계는 해당 연도 12개월 합계와 일치한다.
13. 제목이 없거나 빈 문자열·공백만 있거나 51자 이상이면 저장되지 않는다. 앞뒤 공백은 제거해 저장하고, 이모지 50자 제목은 저장된다.
14. 같은 달의 기록은 날짜 오름차순, 같은 날짜는 등록순으로 조회된다.

## 반복 등록 검증 기준

1. 매주·매월·매년 설정한 수입·지출이 시작일부터 예정일에 자동 등록되어 통계에 반영된다. 아직 등록되지 않은 미래 예정 회차는 집계되지 않는다.
2. 매월 31일 설정은 2027년 2월 28일, 3월 31일에 등록된다. 매년 2월 29일 설정은 평년 2월 28일, 윤년 2월 29일에 등록된다.
3. 매주 반복이 월말·연말을 넘어도 원래 요일을 유지하고, 한국 날짜 기준 예정일에 등록된다.
4. 10월 월세 500,000원 등록 후 설정을 550,000원으로 변경하면 10월 기록·통계는 유지되고 11월 회차부터 550,000원으로 등록된다. 이름·설명·주기 변경도 이미 등록된 기록을 바꾸지 않는다.
5. 자동 등록 기록의 금액·날짜를 수정하거나 삭제하면 해당 기간 통계에 반영되지만 반복 설정과 다른 회차는 유지된다.
6. 동일 회차 처리를 재실행하거나 동시에 실행해도 한 번만 등록된다. 기록의 날짜 수정·삭제 후에도 원래 회차가 재생성되지 않는다.
7. 서비스 재실행 시 누락 회차를 원래 예정일로 보충한다. 설정 변경 전에 도래한 회차는 기존 금액으로, 다음 예정 회차는 변경된 금액으로 등록된다.
8. 반복 중단 시 오늘까지 도래한 회차는 처리하고 이후 회차는 생성하지 않는다. 이미 등록된 기록과 통계는 유지된다.
9. 반복 등록은 수입·지출에만 제공하며, 저축은 직접 등록·수정·삭제할 수 있다.

실제 은행 잔고와의 일치는 검증 범위가 아니다. 잔액 이월 없이 저장한 개별 기록의 기간별 계산 정확성을 검증한다.

## [금지사항]

- 금지사항을 위반한 소스는 반드시 수정하고 재검증한다. 위반 상태의 구현과 금지 예시는 실제 소스 및 최종 반영 대상에 포함하지 않는다.
- 위 기준 중 실패한 항목을 남긴 채 구현 완료로 판단하지 않는다.
- 실패한 검증을 개선사항이나 경고로 낮춰 보고하지 않는다.
- 실제 은행 잔고와의 일치를 검증 통과 조건으로 삼지 않는다.
- 제목 검증을 FE에서만 확인하고 BE·DB 거부 여부를 검증하지 않은 채 통과 처리하지 않는다.
