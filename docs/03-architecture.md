# 기술 구성

## 기술 역할

### Frontend — React

- 수입·지출·저축 입력과 반복 설정 관리 UI
- 수동·자동 등록된 기록의 수정·삭제 및 반복 등록 중단
- 기록 목록 및 통계 표시
- 기간 선택과 API 요청
- 필수 입력값과 금액 형식 안내

### Backend — Node.js

- 반복 설정과 가계부 내역 저장·조회·수정·삭제 및 반복 등록 중단
- 예정 회차 자동 등록, 누락 회차 보충, 회차별 중복 등록 방지
- 날짜와 금액 등 입력값 검증
- 급여 주기 계산 및 기간별 통계 집계
- FE에 동일한 기준으로 계산한 통계 반환

통계 계산의 기준은 BE에 두어 화면마다 결과가 달라지지 않도록 한다. 인증 및 배포 방식은 아직 정하지 않는다.

### 확정 기술 스택

FE와 BE는 저장소 루트 아래 `frontend/`, `backend/`의 독립 프로젝트로 두고 각각 별도 서버에 배포한다.

| 영역 | 선택 |
| --- | --- |
| Frontend | Next.js(App Router) + TypeScript. 브라우저에서 BE를 직접 호출하며 BE 호출은 API 클라이언트 모듈 한 곳에 모은다 |
| Backend | Node.js 24 + TypeScript + Express 5. `routes → services → repositories` 계층과 순수 계산용 `domain`. 입력값·환경변수 검증은 Zod |
| DB | PostgreSQL 16. 로컬은 `backend/`의 docker compose로 실행 |
| DB 접근 | Drizzle ORM + pg. 스키마 변경은 마이그레이션 생성 후 적용 방식만 사용 |
| 테스트 | Vitest. BE는 실제 PostgreSQL 테스트 DB로 API를 검증하고, FE는 React Testing Library를 사용 |

- 금액은 DB에서 정수형(`bigint`, 0보다 큰 값)으로 저장하고 앱에서는 정수로 다룬다.
- 날짜는 DB `date`로 저장하고 앱에서는 `YYYY-MM-DD` 문자열로만 다룬다. 오늘 날짜는 한국 시간 기준으로 BE·FE 각 한 곳에서만 계산한다. FE의 오늘 날짜는 입력 폼의 기본값과 첫 화면 선택 월에만 쓰고, BE는 FE가 보낸 오늘 날짜를 신뢰하지 않는다.
- 기록 제목은 BE가 앞뒤 공백을 제거한 뒤 1~50자(코드포인트 기준)인지 검증하고, 제거한 값을 저장한다. DB에도 같은 조건의 CHECK 제약을 둔다.
- 기록 목록 API는 날짜 오름차순, 같은 날짜는 등록순(`date ASC, id ASC`)으로 반환한다. FE는 이 순서를 그대로 표시한다.
- BE는 허용한 FE 출처에서 온 요청만 CORS로 허용한다.

### 필요한 데이터 개념

| 데이터 | 필요한 정보 |
| --- | --- |
| 통계 기준 | 통계용 급여 기준일. 설정·변경 정책은 미정 |
| 반복 설정 | 이름·설명, 수입·지출 구분, 수입 종류(급여·기타), 금액, 주기, 시작일, 중단 여부 |
| 가계부 기록 | 날짜, 수입·지출·저축 구분, 수입 종류, 해당 기록의 제목(필수)·금액·메모, 자동 등록 시 원본 반복 설정과 회차 식별 정보 |
| 회차 처리 이력 | 반복 설정과 회차 식별 정보, 처리 여부. 개별 기록 수정·삭제 후에도 유지 |

이는 개념 정리이며 최종 DB 스키마는 아니다. 반복 설정과 개별 기록을 분리하고, 통계는 개별 기록에 저장된 값을 사용한다. 설정 변경이 과거 기록이나 통계에 소급 반영되어서는 안 된다.

같은 회차의 중복 등록을 막고, 기록 삭제 후에도 처리 이력을 유지한다. 누락 회차 보충과 설정 변경·중단의 처리 순서를 보장하여 과거 회차에 새 설정값이 적용되지 않도록 한다. 구체적인 스케줄 실행 방식과 저장 구조는 앱 구현 시 결정한다.

## [금지사항]

- 금지사항을 위반한 소스는 반드시 수정하고 재검증한다. 위반 상태의 구현과 금지 예시는 실제 소스 및 최종 반영 대상에 포함하지 않는다.
- FE에서 통계·합계를 계산하지 않는다. 통계 계산 기준은 BE 한 곳에 둔다.
- FE 컴포넌트에서 BE를 직접 `fetch`하지 않는다. BE 호출은 API 클라이언트 모듈 한 곳에 모은다.
- BE가 FE가 보낸 오늘 날짜를 신뢰해 저장·계산 기준으로 쓰지 않는다.
- 금액을 소수(`number` 실수 연산, `numeric` 소수 컬럼)로 저장하거나 0 이하 금액을 허용하지 않는다.
- 날짜를 `Date` 객체로 저장·전달하지 않는다. 앱에서는 `YYYY-MM-DD` 문자열로만 다룬다.
- 이미 적용된 마이그레이션 파일을 고치거나 `drizzle-kit push`로 스키마를 바꾸지 않는다. 스키마 변경은 새 마이그레이션 생성 후 적용한다.
- 기록 목록 정렬 기준을 FE에서 다시 정렬해 BE 순서와 다르게 표시하지 않는다.
- 반복 설정 변경을 과거 기록이나 통계에 소급 반영하지 않는다.
