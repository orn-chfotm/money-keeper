# 달력 하단 날짜 상세 영역 + 건수 표시 + 주말·선택 색

상태: 승인

## Context
달력 칸에 `구분 · 제목 · 금액`이 들어가 복잡하고, 상세를 보려면 팝업을 열어야 한다. 칸은 구분별 건수만 보여주고, 선택한 날짜의 상세는 달력 아래 고정 영역에서 바로 보게 한다.

## PM 요약
- 목표: 달력은 건수로 간략히, 선택 날짜 상세는 하단 영역에 수입→지출→저축 구역별로.
- 범위 (사용자 확정)
  1. 달력 칸: 있는 구분만 건수 표시. 넓은 화면 `수입 1건` 줄 단위, 좁은 화면 `수1 지2` 색 배지(글자 포함). 0건 구분 생략. 제목·금액·"외 N건"·"+N" 제거.
  2. 날짜 클릭은 하단 영역만 갱신(팝업 안 엶). 하단: 날짜 제목, 등록 버튼, 수입/지출/저축 구역(빈 구역 숨김, 구역 안 등록순), 행은 기존 `RecordList` 그대로(제목·구분·급여/기타·금액·메모, 수정/삭제).
  3. 등록·수정 폼만 Dialog. 삭제는 하단에서 기존 AlertDialog 확인.
  4. 최초 진입 시 오늘 선택. 월 이동 시 오늘이 속한 달이면 오늘, 아니면 그 달 1일 선택.
  5. 선택 칸: 옅은 배경 + 테두리 강조. 오늘: 날짜 숫자에 약한 링(선택과 별개).
  6. 토요일 요일·날짜 숫자 파랑, 일요일 빨강(현재 달 칸만. 앞뒤 달 흐린 날짜는 지금처럼 회색).
  7. 저축 색 blue → violet(텍스트·배지·다크 모드).
  8. 수정으로 같은 달 다른 날짜로 옮겨도 선택 날짜 유지. 다른 달 저장 안내·달력 유지 동작 유지.
- 비범위: BE/API/DB, 공휴일 색, 금액 합계 표시, 폼 필드·검증 변경, `useRecords` DTO 마이그레이션, 헤더 아이콘 작업 파일, `backend/src/db/schema.ts`(이 세션 밖 변경, 건드리지 않음).

## CTO 검토
- 리스크 낮음~중간 — FE 표시 계층만 변경. 리스크는 문서 규칙 충돌 3건, 다이얼로그 기반 테스트 재작성 회귀, 로딩/오류 시 하단 "기록 없음" 오표시.
- 함정과 대응
  - 폼 Dialog 재마운트: Ledger에 `formTarget`(create | edit+record) + 열기 카운터, `RecordForm` key에 반영. `open`은 별도 boolean(닫힘 애니메이션 중 내용 유지). 신규 기본 날짜 = 선택 날짜.
  - 하단 로딩·오류: DayPanel에 `isLoading`, `error` 전달. 로딩 중 기록 없으면 "불러오는 중", 오류면 기록 없음 문구 대신 안내. 등록 버튼은 항상 활성.
  - 삭제: `DayDialog.handleDelete` 로직(실패해도 finally reload, `role="alert"` 오류) DayPanel로 이동. 날짜 변경·폼 열기 시 오류 초기화.
  - 접근성: 선택 `aria-pressed`, 오늘 `aria-current="date"`. 칸 이름 `10월 15일, 수입 1건 지출 2건` / `10월 15일, 기록 없음`. 구역 제목은 heading.
  - 일요일 빨강/지출 빨강: 지출은 항상 글자와 함께, 주말 색은 숫자·요일 머리글에만 → 그대로 둠.
  - 건수 집계·구역 그룹화는 컴포넌트 내 `useMemo`(별도 유틸 함수 만들지 않음 → DTO 규칙 대상 아님). 구역 안은 서버 순서 유지 필터만.
- 고아 정리: `day-dialog.tsx` 삭제, `lib/text.ts`의 `truncateText`와 해당 테스트 삭제(`countCodePoints`는 record-form이 사용, 유지).
- 남는 부채(범위 밖): `useRecords(from, to)` 위치 인자, 삭제 후 포커스 body 이동(경미).

## [금지사항]
- 금지사항을 위반한 소스는 반드시 수정하고 재검증한다. 위반 상태의 구현과 금지 예시는 실제 소스 및 최종 반영 대상에 포함하지 않는다.
- 승인 범위 밖 파일(헤더 아이콘 작업 파일, `backend/`)을 수정하거나 같은 커밋에 섞지 않는다.
- 날짜 클릭으로 팝업을 열거나 달력 칸에 제목·금액을 다시 표시하지 않는다.
- 구역 안에서 기록을 재정렬하거나 금액 합계를 화면에서 계산해 표시하지 않는다.
- 구분을 색으로만 표시하고 구분 글자를 생략하지 않는다.
- 로딩·오류 상태에서 "기록이 없습니다"를 표시하지 않는다.
- 건수·그룹화를 DTO 계약 없는 독립 유틸 함수로 빼지 않는다.
- 문서 개정 없이 구현만 반영하지 않는다.
