# Reviewer·Prompter 연결과 오류 처리

## PA → Reviewer → PA 재작업 → PL

1. PA는 구현·검증 후 PL에 반환하기 전에 `reviewer`를 동기 호출한다. 작업 ID, 승인 범위, 변경 파일, diff, 검증 결과, 이전 지적사항을 전달한다.
2. reviewer는 읽기 전용으로 검토하고 PASS / REWORK / BLOCKED를 반환한다. REWORK면 PA가 승인 범위 안에서 수정·검증 후 재검토를 받는다.
3. 범위 밖 수정, MD 변경, 리스크 수용은 BLOCKED로 PL/사용자에게 올린다. BLOCKED는 완료가 아니다.
4. PASS 이후 코드가 바뀌면(통합 단계 포함) 다시 검토받는다.
5. PL은 PASS 최종본만 통합한다.
6. 사용자 보고에는 reviewer 기준·추천, PA 실제 수정, PL 수용/보류 결정과 이유, 재검증 결과를 포함한다. 추천이 없으면 `없음`으로 적는다.

중첩 Agent 호출이 막히면 검토 완료를 주장하지 않고 BLOCKED로 보고한다. 메인 세션이 reviewer 호출과 PA 재작업을 중계한다.

## 훅이 보장하지 않는 것

PA SubagentStop 훅은 보고 형식(`REVIEWER_STATUS`, `🔎 Reviewer 검토:`, `🔁 ...:`)의 누락만 막는다. 실제 reviewer 호출 여부나 검토 품질은 인증하지 않으므로 PA/PL이 실제 reviewer 응답과 최종 코드가 일치하는지 확인한다.

## Prompter 호출

- 반복 지시, MD 규칙 충돌, 문서 누락을 발견하면 메인 세션·PL·PA가 `prompter`를 호출한다. PM/CTO는 호출 필요성을 호출자에게 전달한다.
- 호출자는 관련 대화 요약, 작업 목표, 대상 MD 경로, 승인 범위를 전달한다. prompter는 대화를 자동 감시하지 않는다.
- MD 변경 반영 기준은 `04-prompt-authoring.md`를 따른다.

## 오류 분류와 되돌림

| 오류 | 되돌릴 단계 |
|---|---|
| 범위 오류 (요구사항·범위 변경) | PM |
| 기술 방향·설계 오류 | CTO |
| 작업 분리·통합 충돌 | PL |
| 구현 오류·실행 오류 | PA (PL이 원인 검증 후 재작업 지시) |
| 승인 범위 이탈 | 사용자 승인 요청 |

- PA는 새 지시 없이 실패를 우회하거나 범위를 넓혀 재진행하지 않는다.
- 반복 가능한 오류, 테스트·빌드 실패, 보안·권한·데이터 손상 가능성, 승인 범위 이탈은 `/review-log`로 기록을 제안한다.

## 테스트 보고

- 가능한 테스트는 실행한다. 실행하지 못한 테스트는 이유를 남긴다.
- 실패한 테스트를 숨기거나 개선사항으로 낮춰 보고하지 않는다.
- 실패 원인이 작업 범위 밖이면 PL 또는 CTO로 에스컬레이션한다.

```md
## 테스트 결과
- 실행한 테스트 / 결과:
- 실패 항목 / 원인:
- 미실행 테스트 / 사유:
```
