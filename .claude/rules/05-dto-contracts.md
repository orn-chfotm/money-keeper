# DTO 함수 계약

- 새로 작성하거나 시그니처를 수정하는 프로젝트 소유 함수는 하나의 `XxxRequestDto` 객체를 입력받고, 반환 타입을 `XxxResponseDto` 또는 `Promise<XxxResponseDto>`로 명시한다. 입력·출력 DTO는 이름 있는 객체 형태의 `type` 또는 `interface`로 정의한다. 둘 다 허용하며 주변 코드의 관례를 따른다. 이 규칙만을 이유로 기존 `type`과 `interface`를 서로 변환하지 않는다.
- 위치 기반 원시값 인자, 여러 인자, 인라인 객체 타입 대신 이름 있는 DTO를 사용한다. `param: XxxRequestDto` 또는 `{ field }: XxxRequestDto`로 선언하며, 불필요한 `{ param: ... }` 중첩은 만들지 않는다.
- 원시값·배열 결과도 응답 DTO의 의미 있는 필드(`isValid`, `amount`, `items` 등)에 담는다. 입력이 없는 함수는 인자를 생략하고, 결과가 없는 명령은 `void` / `Promise<void>`를 허용한다. 빈 DTO를 만들지 않는다.
- API 클라이언트, 서비스, 저장소, 프로젝트 소유 훅·유틸리티에 적용한다. React 컴포넌트는 기존 Props 계약을 유지한다. 라이브러리·프레임워크가 정한 콜백, 이벤트 핸들러, override, 외부 라이브러리 함수는 해당 시그니처를 유지하고 필요한 곳에서 DTO 함수로 연결한다.
- 계층별 의미가 같으면 DTO를 재사용하고, DB 행 타입을 API 응답 계약으로 직접 노출하지 않는다. 계층마다 의미 없이 동일 DTO를 복제하지 않는다.
- `any`, 타입 단언, 위치 인자 호환 오버로드로 계약을 우회하지 않는다. TypeScript 계약과 외부 입력의 런타임 검증을 함께 유지한다.
- 기존 함수 변경 시 승인된 범위의 호출부·테스트도 함께 갱신한다. 범위 밖 변경이 필요하면 PL에 보고한다. 이 규칙만으로 전체 코드 마이그레이션이나 HTTP 응답 형식 변경을 시작하지 않는다.
- PA는 구현 전 이 규칙과 [dto-contracts skill](../skills/dto-contracts/SKILL.md)을 Read로 읽고, reviewer에게 DTO 계약 준수 여부를 검토 기준으로 전달한다.

## [금지사항]

- 금지사항을 위반한 소스는 반드시 수정하고 재검증한다. 위반 상태의 구현과 금지 예시는 실제 소스 및 최종 반영 대상에 포함하지 않는다.
- 작업 범위 내 DTO 위반은 함수·호출부·관련 테스트를 함께 수정한 뒤 검증한다. 범위 밖 수정이 필요하면 PL에 위반 위치·이유·필요 범위를 보고하고 해당 작업을 보류한다. TODO나 경고만 남긴 채 완료 처리하지 않는다.
- 적용 대상 함수에 `listRecords(from: string, to: string)`처럼 위치 인자를 정의하지 않는다.
- `type FindRequestDto = string`처럼 이름만 DTO인 원시값 타입이나 인라인 타입으로 객체 DTO 계약을 대체하지 않는다.
- 반환 타입을 생략하거나 `number`, `RecordDto[]` 등을 응답 DTO 없이 직접 반환하지 않는다. 본문에서 허용한 `void` 명령은 제외한다.
- `any`, `as XxxResponseDto`, 위치 인자 오버로드로 잘못된 입력·출력을 숨기지 않는다.
- `type` 또는 `interface` 중 하나만 허용한다고 해석하지 않는다.
- 라이브러리가 정한 콜백·React Props 계약을 강제로 DTO 형식으로 변경하지 않는다.
- 호출부·테스트를 남겨 둔 채 함수 선언만 바꾸거나, DTO 도입을 이유로 런타임 검증을 제거하지 않는다.
- 승인 범위 밖 마이그레이션이나 공개 HTTP 응답 형식 변경을 진행하지 않는다.
