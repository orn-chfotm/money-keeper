# MD 작성·정리 규칙

## 적용 범위

`docs/`, `.claude/rules/`, `.ai/reviews/` 등 이 프로젝트에서 작성하는 모든 MD 문서. 단, `.claude/agents/`, `.claude/commands/`는 Claude Code 형식을 따른다(`04-prompt-authoring.md`).

## frontmatter

모든 MD 상단에 문서 목적을 한 문장으로 적은 `description`을 둔다.

```md
---
description: "문서의 목적을 한 문장으로 설명합니다."
---
```

## 번호와 구조

- 문서 디렉토리의 첫 파일은 `00-index.md`다. 디렉토리 목적, 파일 목록, 읽는 순서를 적는다.
- 나머지 파일은 `01-*`, `02-*`처럼 1단위 번호 + kebab-case 주제명으로 짓는다. 번호는 읽는 순서를 따른다.
- 대분류 디렉토리를 나눌 때는 `00-*`, `10-*`, `20-*`처럼 10단위 번호를 쓴다.
- 대분류 아래 하위 디렉토리는 번호 없이 주제명만 쓴다.

## 생성 기준

- 새 문서를 만들기 전에 기존 MD 보완으로 해결되는지 먼저 확인한다.
- 새 문서가 필요하면 위치와 이유를 먼저 사용자에게 제시하고 승인받는다.
- 기존 문서의 구성, 용어, 문체를 따른다.
- 요청 밖 문서나 내용을 만들지 않는다.

## 필수 하단 섹션

- MD를 생성하거나 수정할 때 문서의 마지막 섹션을 정확히 `## [금지사항]`으로 작성한다. agent·command·skill 문서에도 적용하며 각 도구의 필수 frontmatter와 파일명은 유지한다.
- 본문의 규칙에 반대되는 행동·구현·호출 사례를 구체적인 목록으로 나열한다. 코드 규칙은 가능한 경우 잘못된 코드 예시도 포함하고, 금지 예시임을 명시한다.
- 금지사항은 반드시 준수할 제약이다. 작성·구현 전 확인하고 완료 전 위반 여부를 점검한다. 단순 권고나 임의로 생략할 수 있는 체크리스트로 취급하지 않는다.
- 각 문서의 금지사항에는 다음 처리 원칙을 명시한다: "금지사항을 위반한 소스는 반드시 수정하고 재검증한다. 위반 상태의 구현과 금지 예시는 실제 소스 및 최종 반영 대상에 포함하지 않는다." 금지 예시는 문서 설명 또는 격리된 검증 용도로만 사용한다.
- 작업 범위에서 발견한 위반은 수정·재검증 후에만 완료 처리한다. 범위 밖 수정이 필요하면 위반 위치·이유·필요한 수정 범위를 보고하고 해당 작업을 보류한다. 경고나 TODO만 남겨 위반을 해결한 것으로 처리하지 않는다.
- 본문이 명시적으로 허용한 예외와 규칙 위반 사례를 구분한다. 허용된 예외를 금지 목록에 넣거나 금지 예시를 허용 예외로 해석하지 않는다.
- 기존 `## 금지` 등 같은 목적의 섹션은 이름을 통일하고 맨 아래로 이동한다. 본문과 중복되거나 충돌하는 별도 규칙을 만들지 않는다.
- 이 규칙 도입만으로 기존 MD 전체를 수정하지 않는다. 이후 생성·수정하는 문서에 적용한다.

## 이동·이름 변경

문서를 옮기거나 이름을 바꾸면 같은 작업 안에서 다음을 함께 갱신한다.

- 해당 디렉토리의 `00-index.md`
- 다른 문서의 상대 링크와 앵커 링크
- `.claude/agents`, `.claude/commands`, `.claude/rules` 안의 경로
- 문서 내부의 예시 경로

## 경계

- `docs/`는 제품 요구사항·정책 등 tool 중립 문서다. Claude 전용 문법이나 설정을 넣지 않는다.
- Claude 실행 규칙·설정은 `.claude/`에 둔다.
- 리뷰·설계·피드백 기록은 `.ai/reviews/<category>/`에 둔다(`/review-log`).
- 외부 하네스 submodule 내부에는 프로젝트 문서나 기록을 남기지 않는다.

## 파일 탐색 원칙

매 작업마다 repository 전체를 스캔하지 않는다.

1. 사용자가 언급한 파일을 먼저 읽는다.
2. 그 파일이 참조하는 가까운 문서를 읽는다.
3. 필요하면 해당 디렉토리의 `00-index.md`를 읽는다.
4. 그래도 부족할 때만 범위를 제한해 검색한다.

전체 스캔이 필요하면(전체 구조 검토 요청, 깨진 참조, 재구조화) 목적과 범위를 먼저 설명한다.

## [금지사항]

- 금지사항을 위반한 소스는 반드시 수정하고 재검증한다. 위반 상태의 구현과 금지 예시는 실제 소스 및 최종 반영 대상에 포함하지 않는다.
- 위반을 발견하고도 경고·TODO만 남긴 채 수정 완료나 검증 통과로 보고하지 않는다. 범위 밖 수정이 필요하면 해당 작업을 보류하고 보고한다.
- MD를 생성·수정하면서 `## [금지사항]`을 누락하거나 다른 제목으로 대체하지 않는다.
- 금지사항 뒤에 다른 섹션을 추가해 마지막 섹션 요건을 깨뜨리지 않는다.
- “잘 작성한다”처럼 위반 행동을 알 수 없는 문장만 나열하지 않는다.
- 본문에서 허용한 예외를 금지하거나 금지 예시를 권장 구현으로 제시하지 않는다.
- 문서가 짧거나 예시라는 이유로 금지사항 작성·준수 확인을 생략하지 않는다.
- 요청 범위 밖 문서를 일괄 수정하거나 도구가 요구하는 frontmatter·파일명을 훼손하지 않는다.
